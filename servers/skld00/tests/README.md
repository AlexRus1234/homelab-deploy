# `tests/` — регрессия контура узла skld00

Харнессы живут **в репозитории**, а не в рабочем кэше: раньше они были во временном каталоге и были
вычищены по неактивности — вместе с единственным доказательством, что ветки контура работают.

Узел для прогона не нужен: `incus-loc` и `zfs` подменяются заглушками, их «состояние» живёт в файлах
временного каталога. Ничего настоящего не мутируется.

```sh
bash servers/skld00/tests/update-test.sh      # ночной контур: обновление, откат, уборка
bash servers/skld00/tests/reconcile-test.sh   # контур применения: декларации, uid, хеши, пересоздание
bash servers/skld00/tests/remove-test.sh      # ветка снятия: декларация удалена из git
```

Каждый харнесс печатает по секциям, что делает (`=== 1. …`), по каждой проверке — строку `ok` или `FAIL`
с ожиданием и фактом, а в конце итог (`проверок N, провалов M`); при расхождении возвращает ненулевой
код. Сравнения берутся из `harness-lib.sh` (`check`, `has`, `nothas`, `differs`) — без них прогон был бы
всегда зелёным и не годился бы ни для хука, ни для CI.

## Проверка перед пушем (git-хук `pre-push`)

В репозитории лежит [`.githooks/pre-push`](../../../.githooks/pre-push): он гоняет три харнесса и **не
пускает пуш**, если что-то красное (печатает только итоги и строки `FAIL`). Включается ОДИН раз на клон —
настройка репозиторная, пишется в `.git/config` этого клона:

```sh
git config core.hooksPath .githooks        # из корня клона; то же самое, что git config --local
```

**Стягиваешь репозиторий на другую машину — включи заново:** у нового клона свой `.git/config`, сам хук
(скрипт) приезжает из репозитория, но не включается сам.

```sh
git clone <репозиторий> homelab-deploy
cd homelab-deploy
git config core.hooksPath .githooks                 # одна строка
bash servers/skld00/tests/update-test.sh            # убедиться, что харнессы здесь гоняются
```

Нужны только `bash` и обычные утилиты (`git`, `mktemp`, `date`, `grep`, `awk`, `sed`): узла, root, Incus и
ZFS харнессы не касаются. Прогон трёх харнессов — около 11 секунд.

Почему не `git config --global core.hooksPath …`: глобальная настройка подменяет каталог хуков **всем**
репозиториям машины — их собственные `.git/hooks/*` молча перестают работать. Поэтому только настройка
репозитория.

Обойти проверку осознанно: `git push --no-verify`.

Чего этот хук (как и любой CI на этих харнессах) не проверяет: живого поведения Инкуса и ZFS, cloud-init,
прав на датасетах, таймингов — это остаётся живым репетициям и ночному прогону. Он ловит регрессии в
проекциях и парсерах, порядок команд, наборы «оставить/снести», обработку флагов и выключателя, имена
метрик и синтаксис скриптов.

### Правило времени в фикстурах

Любая метка времени в харнессе строится **относительно «сейчас»** — `stamp_ago <секунд>` из
`harness-lib.sh` (обратный разбор — `stamp_age`), и никогда не пишется датой. Жёсткая дата зеленеет в
день написания и краснеет через сутки: 16.10 фикстура объявляла окно удержания 24 ч и ставила «свежую»
стоянку меткой `20261016-050000`; к 17.10 ей стало 41,7 ч, контур снёс её **правильно**, а харнесс ждал
обратного — пять проверок легли, и чужой пуш был заблокирован (ушёл через `--no-verify`).

Отсюда три правила: (1) фикстуры со временем — только через `stamp_ago`; (2) посылка фикстуры
проверяется отдельной проверкой («свежая стоянка действительно внутри окна 24 ч») — тогда гниение теста
падает как гниение теста, с внятной строкой, а не как «контур сломался»; (3) `pre-push` падает на любой
абсолютной метке времени в `tests/` — до запуска харнессов, с указанием строки.

### `update-test.sh` — ночной контур (`update.sh`)

| Секция | Что проверяется |
| :--- | :--- |
| A | `--dry-run`: печатает план и не делает ни одной мутирующей команды |
| B | успешное обновление: снапшот инстанса и датасета → флаг внутри → `zypper dup` → перезапуск → свежий маркер → проба → флаг снят |
| C1 | `dup` упал → откат: `stop` → `snapshot restore` → `zfs rollback` → `start` → проба |
| C2 | проба после обновления упала → откат (вторая проба зелёная) |
| C3 | маркер загрузки не посвежел (перезапуска не было) → откат; откат не помог → флаг оставлен, «нужен человек», ненулевой код |
| D | флаг прошлого прогона на старте → сразу откат, `zypper` не вызывается |
| E | уборка: живой сервис чистится (окно 24 ч, потолок N=3, стоянки), лежащий (STOPPED) и нездоровый (проба падает) — нет; «свежесть» считается по метке времени в имени, поэтому фикстуры нарочно со смешанными префиксами (для инстанса наши — `pre-`/`update-`, для датасета — `pre-`/`recreate-`, и объект с чужим префиксом снимать нельзя); посылки фикстуры (что «свежая» стоянка внутри окна, а снимаемые — старше) проверяются отдельными строками; итог уборки попадает в файл отчёта |
| E2 | второй прогон уборки: снимать уже нечего → `lxc_snapshots_deleted_last_run = 0`, а накопительный `lxc_snapshots_deleted_total` не растёт |
| F | выключатель `/etc/lxc-automation.off`: только отчёт, ноль мутаций и строки «пропуск: автоматика выключена» в файле отчёта |

### `reconcile-test.sh` — применение деклараций (`reconcile.sh`)

| Секция | Что проверяется |
| :--- | :--- |
| 1 | `bash -n` и «инстанса нет» → в отчёте план создания (и ни одной мутации) |
| 2 | разбор декларации: какие ключи читаются, что попадает в скаляры, что в состав |
| 3 | карта uid: `Hostid + uid − Nsid` (478 → 100478, 479 → 100479, 0 → 100000) |
| 4 | чувствительность хешей: правка скаляра меняет только скаляры, правка `devices`/`user-data` — только состав, правка **только комментариев** не меняет ничего |
| 5 | инстанс есть, скаляры разошлись → план `config set` по каждому ключу |
| 5б | в состоянии старая **версия проекции** → хеши пересчитываются, пересоздания нет, запись состояния переписывается в новый формат |
| 6 | инстанс есть, состав изменился → план пересоздания |
| 7 | пересоздание вживую (заглушки): `zfs snapshot` → `stop` → `rename` (стоянка, не `delete`) → `create` → `start` → cloud-init → uid → проба; в отчёте `recreate ok`; состояние записывается с версией проекции |
| 8 | файл отчёта |

`chown` тоже заглушка, поэтому root для прогона не нужен.

### `remove-test.sh` — снятие по удалённой из git декларации

| Секция | Что проверяется |
| :--- | :--- |
| 0 | готовит настоящий git-репозиторий во временном каталоге: коммит с тремя декларациями → коммит, где две удалены |
| A | декларация с маркером удалена → снапшот данных (`@removed-…`) → `stop` → `delete`, датасет остаётся; инстанс **без** маркера не трогается; декларация, которая на месте, не задевается |
| B | то же при выключенной автоматике: только план, ноль вызовов снятия |
| C | та же ревизия (ничего не удалено) → снимать нечего |
| D | строки отчёта (`delete ok` / `delete пропуск` с причиной) |
