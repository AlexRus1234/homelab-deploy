# `tests/` — регрессия контура узла skld00

Харнессы живут **в репозитории**, а не в рабочем кэше: раньше они были во временном каталоге и были
вычищены по неактивности — вместе с единственным доказательством, что ветки контура работают.

Узел для прогона не нужен: `incus-loc` и `zfs` подменяются заглушками, их «состояние» живёт в файлах
временного каталога. Ничего настоящего не мутируется.

```sh
bash servers/skld00/tests/update-test.sh      # ночной контур: обновление, откат, уборка
bash servers/skld00/tests/reconcile-test.sh   # контур применения: декларации, uid, хеши, пересоздание
bash servers/skld00/tests/remove-test.sh      # ветка снятия: декларация удалена из git
```

Все три возвращают ноль при успехе и печатают по секциям то, что проверяют (`=== 1. …`), — расхождение
видно глазами, без ассертов и без выхода ненулевым кодом.

### `update-test.sh` — ночной контур (`update.sh`)

| Секция | Что проверяется |
| :--- | :--- |
| A | `--dry-run`: печатает план и не делает ни одной мутирующей команды |
| B | успешное обновление: снапшот инстанса и датасета → флаг внутри → `zypper dup` → перезапуск → свежий маркер → проба → флаг снят |
| C1 | `dup` упал → откат: `stop` → `snapshot restore` → `zfs rollback` → `start` → проба |
| C2 | проба после обновления упала → откат (вторая проба зелёная) |
| C3 | маркер загрузки не посвежел (перезапуска не было) → откат; откат не помог → флаг оставлен, «нужен человек», ненулевой код |
| D | флаг прошлого прогона на старте → сразу откат, `zypper` не вызывается |
| E | уборка: живой сервис чистится (окно 24 ч, потолок N=3, стоянки), лежащий (STOPPED) и нездоровый (проба падает) — нет; «свежесть» считается по метке времени в имени, поэтому фикстуры нарочно со смешанными префиксами; итог уборки попадает в файл отчёта |
| E2 | второй прогон уборки: снимать уже нечего → `lxc_snapshots_deleted_last_run = 0`, а накопительный `lxc_snapshots_deleted_total` не растёт |
| F | выключатель `/etc/lxc-automation.off`: только отчёт, ноль мутаций и строки «пропуск: автоматика выключена» в файле отчёта |

### `reconcile-test.sh` — применение деклараций (`reconcile.sh`)

| Секция | Что проверяется |
| :--- | :--- |
| 1 | `bash -n` и «инстанса нет» → в отчёте план создания (и ни одной мутации) |
| 2 | разбор декларации: какие ключи читаются, что попадает в скаляры, что в состав |
| 3 | карта uid: `Hostid + uid − Nsid` (478 → 100478, 479 → 100479, 0 → 100000) |
| 4 | чувствительность хешей: правка скаляра меняет только скаляры, правка `devices`/`user-data` — только состав, правка **только комментариев** не меняет ничего |
| 5 | инстанс есть, скаляры разошлись → план `config set` по каждому ключу |
| 6 | инстанс есть, состав изменился → план пересоздания |
| 7 | пересоздание вживую (заглушки): `zfs snapshot` → `stop` → `rename` (стоянка, не `delete`) → `create` → `start` → cloud-init → uid → проба; в отчёте `recreate ok` |
| 8 | файл отчёта |

`chown` тоже заглушка, поэтому root для прогона не нужен.

### `remove-test.sh` — снятие по удалённой из git декларации

| Секция | Что проверяется |
| :--- | :--- |
| 0 | готовит настоящий git-репозиторий во временном каталоге: коммит с тремя декларациями → коммит, где две удалены |
| A | декларация с маркером удалена → снапшот данных (`@removed-…`) → `stop` → `delete`, датасет остаётся; инстанс **без** маркера не трогается; декларация, которая на месте, не задевается |
| B | то же при выключенной автоматике: только план, ноль вызовов снятия |
| C | та же ревизия (ничего не удалено) → снимать нечего |
| D | строки отчёта (`delete ok` / `delete пропуск` с причиной) |
