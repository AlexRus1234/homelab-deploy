
# GitOps-агент: Pull-модель и Автоматизация (Webhook)

Механизм автоматизации состоит из двух компонентов: **сервера Webhook** и **Bash-скрипта синхронизации**.

## 1. Слушатель событий (Webhook)
На каждой виртуальной машине (хосте контейнеров) запущен бинарный файл `adnanh/webhook` в качестве системной службы.

*   **Функция:** Ожидание POST-запросов от центрального сервера Forgejo.
*   **Безопасность:** Запрос обрабатывается только в том случае, если HTTP-заголовок `X-Gitea-Signature` содержит корректную криптографическую подпись (HMAC SHA-256), совпадающую с локальным секретным ключом. Это исключает несанкционированный запуск обновлений.
*   **Действие:** При получении валидного сигнала (Push Event в ветку `main`), сервер выполняет локальный скрипт `sync-state.sh`.

## 2. Изоляция контекста (Sparse-Checkout)
Так как все конфигурации для всех виртуальных машин хранятся в едином монорепозитории (`homelab-deploy`), клонирование всего репозитория на каждый хост является небезопасным и избыточным.

Используется функционал Git **Sparse-Checkout** (современный режим `--sparse`):
```bash
# Пример для ВМ obshaga (yadr00)
git clone --filter=blob:none --sparse https://git.yadr00.internal/AlexRus1234/homelab-deploy.git /opt/appdata/git-repo
cd /opt/appdata/git-repo
git sparse-checkout set servers/yadr00/obshaga
```
Для ВМ `panelka` вместо пути указывается `servers/yadr01/panelka`. ВМ загружает только ту директорию, которая относится к ней — ВМ «Общежитие» физически не имеет доступа к пайплайнам или конфигурациям ВМ «Панелька».

## 3. Логика работы `sync-state.sh`
Скрипт синхронизации написан с учетом идеологии идемпотентности (многократный запуск приводит к одному и тому же правильному результату).

### 3.1. Синхронизация с Git
```bash
git pull origin main
```
Скрипт подтягивает актуальное состояние ветки `main` в локальную копию репозитория. Перед и после `pull` фиксируются хеши коммита (`OLD_HASH` / `NEW_HASH`) — они используются на последующих этапах для вычисления удалённых и изменённых файлов. При отсутствии изменений скрипт завершает работу досрочно после `podman auto-update`.

### 3.2. Обработка удалений (Очистка)
```bash
DELETED_FILES=$(git diff --name-only --diff-filter=D $OLD_HASH $NEW_HASH ...)
```
Перед применением новых конфигураций скрипт анализирует удаленные файлы. Если `.container` файл был удален или переименован в Git, скрипт **останавливает** (`systemctl stop`) соответствующую системную службу до того, как удалит конфигурацию. Это предотвращает возникновение служб-призраков с зависшими сетевыми портами.

### 3.3. Зеркалирование (Rsync)
Для переноса файлов из скачанного репозитория в системные папки Podman используется `rsync`.
*   **Папка Quadlets (`--delete`):** `rsync -rlptD --delete`. Гарантирует, что папка `~/.config/containers/systemd/` становится точной копией репозитория. Весь мусор удаляется.
*   **Папка App-Configs (Без удаления):** `rsync -rlptD`. Конфиги копируются **без** ключа `--delete`. Это критически важно, так как в целевой папке на ВМ находятся "боевые" `.env` файлы с реальными паролями, которых нет в Git-репозитории.

### 3.4. Обновление образов (Podman Auto-Update)
```bash
podman auto-update
```
Скрипт дает команду демону Podman проверить локальный реестр образов. Если для контейнеров (у которых прописан флаг `AutoUpdate=registry`) появилась новая сборка с тегом `:latest`, Podman самостоятельно скачивает слои, останавливает контейнер и перезапускает его на новом образе.

### 3.5. Перезапуск служб (гибридная логика)
```bash
CHANGED_FILES=$(git diff --name-only --diff-filter=AM $OLD_HASH $NEW_HASH ... | grep '\.container$')
```
По умолчанию скрипт анализирует только изменённые или добавленные (`--diff-filter=AM`) Quadlet-файлы и выполняет `systemctl restart` **точечно**, минимизируя даунтайм сервисов. Неизменённые контейнеры не затрагиваются.

Для случаев, когда требуется гарантированно перезапустить все службы (например, после изменения структуры каталогов, правок самого `sync-state.sh` или обновления общих образов), предусмотрен **принудительный полный перезапуск** через переменную окружения:
```bash
FORCE_FULL_RESTART=1 /opt/appdata/git-repo/.../sync-state.sh
```
При `FORCE_FULL_RESTART=1` скрипт проходит по всем `~/.config/containers/systemd/*.container` и перезапускает каждую службу. По умолчанию (`FORCE_FULL_RESTART` не задан или `0`) применяется точечный режим.
