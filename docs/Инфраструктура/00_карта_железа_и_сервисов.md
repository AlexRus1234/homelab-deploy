## 4. Узел SKLD00 — NAS / Data-слой

### 4.1. Железо и диски

Jonsbo N4 (Mini-ITX, корзина горячей замены, деревянная панель), Intel Core i3-1115G4, 32 ГБ, 2× NVMe + 6× HDD, 2.5 Gbps (упор ~270 МБ/с), стример **LTO-4 / LTO-5** для офлайн-бэкапа.

| Носитель | Разметка / ФС | Назначение |
| :--- | :--- | :--- |
| NVMe p1 | FAT32 EFI на обоих дисках | дублированный GRUB |
| NVMe p2 | **Btrfs RAID1** | система (`/`) |
| NVMe p3 | **Btrfs RAID0** (метаданные RAID1), 340 GiB | кэш загрузок `/mnt/torent` |
| NVMe p4 | **ZFS Mirror**, 350 GiB | special vdev для пула `tank` |
| 6× HDD | **ZFS RAIDZ2** — пул `tank` | основное хранилище `/tank/data` |

Тюнинг: `sync=disabled`, `special_small_blocks=0`, `compression=zstd`, `recordsize` PostgreSQL `16k` / MongoDB `64k`. Обслуживание: ежемесячный авто-scrub (1-го числа), Snapper на корне Btrfs (откат из GRUB).

### 4.2. Сетевые адреса (macvlan)

| Сервис | IP | Порт |
| :--- | :--- | :--- |
| Хост (Samba/SMB) | `172.20.50.1` | 445 |
| PostgreSQL | `172.20.50.10` | 5432 |
| MongoDB | `172.20.50.11` | 27017 |
| Valkey (Redis) | `172.20.50.12` | 6379 |
| RustFS (S3) — по P2P-линку | `172.21.6.249` | 9000 |

Все БД слушают **только** свои macvlan-IP и адреса P2P-линка; `0.0.0.0`/localhost запрещены.

| Сервис | Детали |

### 5.3. Стандарт ВМ (модель «pets»)

- ОС Arch Linux (минимальная серверная), Q35, QEMU Guest Agent, SeaBIOS, 3–6 ядер, 8192 МБ RAM (баллунинг выключен), VirtIO.
- Два диска: **sda (OS) 12 ГБ** — расходник; **sdb (Data) 1 ГБ** → `/opt/appdata/db` ext4 с `noatime,discard` (БД/токены/файлы, ежедневный инкрементный бэкап).
- Всё от пользователя **`app-runner`** (root запрещён, `loginctl enable-linger`), rootless Podman + Systemd Quadlets; опубликованные порты — от **10000+** (нумерация независима на каждую ВМ).
- Конфиги: `/opt/appdata/config/quadlets/` (симлинк в `~/.config/containers/systemd/`) и `/opt/appdata/config/<service>/`; секреты — только в `.env` на ВМ.
- Доверие PKI: корневой сертификат CA в `/etc/ca-certificates/trust-source/anchors/` + `update-ca-trust`.

## 8. Как всё связано

### 8.1. Сеть

```text
                         Интернет
                            │
                  VPS (Caddy, Headscale/DERP, Coturn, CrowdSec)
                            │  Tailscale (маршрут 172.20.0.0/16)
        ┌───────────────────┴────────────────────┐
        │              SHLZ00 (шлюз)             │
        │  nftables · AdGuard→dnsmasq→Unbound    │
        │  Step-CA · CAKE-шейпер                 │
        │  Zeek/Suricata/CrowdSec · Intermasq    │
        └───┬──────────────┬──────────────┬──────┘
       LAN 172.20.0.0/16  │              │  IoT 172.22.0.0/16 / Rescue 192.168.99.0/24
            │             │              │
     ┌──────┴─────┐ ┌─────┴──────┐  ┌────┴──────┐
     │  YADR00    │ │  YADR01    │  │  SKLD00   │
     │ N100/32ГБ  │ │ R7 5800HS  │  │ i3/32ГБ   │
     │ vmbr0      │ │ vmbr0      │  │ 6×HDD ZFS │
     └──────┬─────┘ └──┬───┬─────┘  │ macvlan БД│
            │          │   │        └─────┬─────┘
     Caddy .5.3   Caddy .6.2 │   PostgreSQL/MongoDB/Valkey/Samba
     Forgejo .5.2   PBS .6.3 │   RustFS S3 (P2P)

     obshaga .5.17  bridge .6.6
                    sftpgo .6.8
                    gitrunner .6.7
                    panelka .6.9 ──────► vmbr1 172.21.6.0/24 (2.5G, без коммутатора)
```

### 8.2. Цепочки

- **GitOps (основная)**: push в Forgejo → webhook (HMAC SHA-256) на ВМ `obshaga`/`panelka` `:9000` (на узле `skld00` — `:9002`) → `sync-state.sh` → `git pull` (sparse-checkout только своей папки) → `rsync` quadlets (`--delete`) и app-configs (без `--delete`, чтобы не стереть боевые `.env`) → `systemctl --user daemon-reload` → старт `.network`-юнитов → `podman auto-update` → `systemctl restart` только изменённых юнитов. Второй путь обновления образов — таймер `podman-auto-update.timer` в окне 03:00–04:00.
- **Конфигурация LXC** (`caddy`, `sftpgo`, `intermasq`): отдельные workflow по SSH от `root` с общим секретом `SSH_PRIVATE_KEY`.
- **PKI**: Step-CA на SHLZ00 выдаёт сертификаты зоны `.internal` по ACME → Caddy на узлах; корневой сертификат раздаётся из `https://172.20.0.1:9000/roots.pem` и импортируется на ВМ (доверие Podman к локальному реестру) и в браузеры.
- **DNS/DHCP**: статические привязки MAC→IP ведутся в dnsmasq через панель Intermasq (таблица dnsmasq — источник правды по адресации); маршруты в Caddy — через Admin API (`:2019`) или статические Caddyfile.
- **Данные**: приложения (Forgejo, Authentik, Synapse, SFTPGo, Khrazhevnik) ходят в PostgreSQL/Valkey/MongoDB на macvlan-адреса NAS; объектные данные — в RustFS по P2P-линку, минуя коммутатор.
- **Бэкапы**: хосты PVE (`/etc`) → скрипт `/root/backup-host.sh` → PBS (namespaces `yadr00`/`yadr01`) → datastore `shara` на SMB-шаре NAS; гости — nightly snapshot ~23:00 (все, кроме CT 101 самого PBS); PBS — вручную vzdump'ом на шару; на NAS система под Snapper, данные под ZFS scrub + LTO.
- **Внешний доступ**: публичные домены проксирует Caddy на VPS либо напрямую в ВМ, либо через внутренние Caddy-домены с `tls_insecure_skip_verify`; удалённый доступ в LAN — через Headscale (роутер анонсирует `172.20.0.0/16`) со split-DNS на `.internal`.
