# Автообновление контейнеров Podman (auto-update)

> [!abstract] Суть
> `AutoUpdate=registry` в Quadlet — это только **политика** («контейнер можно обновлять»), а не триггер. Обновление происходит только в момент выполнения команды `podman auto-update`. Механизм состоит из **трёх частей**, и без последней ничего не работает «само».

## Три компонента системы

| Компонент | Роль | Где у нас |
| :--- | :--- | :--- |
| `AutoUpdate=registry` в `.container` | Политика: отметить контейнер как обновляемый | в каждом Quadlet |
| `podman auto-update` (команда) | Исполнитель: сравнить digest, скачать образ, перезапустить юнит | вызывается из `sync-state.sh` при пуше |
| `podman-auto-update.timer` | Периодичность (иначе «сам» не делает ничего) | user-таймер, окно 03:00–04:00 |

> [!warning] Главная ловушка
> Туториалы часто пишут «добавь `AutoUpdate=registry` и Podman будет сам обновлять». Это неверно **без включённого таймера** (или другого планировщика). Именно так у нас «зависли» образы nora и memos: контейнеры помечены, а команда не вызывалась.

## Политики

| Значение | Поведение |
| :--- | :--- |
| `registry` | Сравнивает digest локального образа с digest в реестре для того же тега (`:latest`). Новый digest → pull → пересоздание |
| `local` | Для локально собранных образов: берёт более свежий образ из локального хранилища |
| (без флага) | Контейнер игнорируется автообновлением |

Обновляются **только контейнеры под systemd** (Quadlet-юниты). Голые `podman run` не трогаются.

## Как происходит обновление

- Контейнер перезапускается **как systemd-юнит**: stop → удалить контейнер → создать из нового образа. Все опции Quadlet (`UserNS`, volumes, env) сохраняются.
- Обновляется только то, у чего реально сменился digest — соседние контейнеры не затрагиваются.
- Даунтайм — секунды на контейнер, без blue-green.

## Rollback

> [!info] Откат на предыдущий образ — главная фишка против Watchtower (который для этого просто не существует в природе)
>
> - **Базовый уровень** (всегда): systemd не получил `READY=1` → контейнер упал на старте → автоматический откат.
> - **Продвинутый** (нужны `HealthCmd` + `Notify=healthy` в `.container`): `READY` отправляется только при зелёном healthcheck → откат, если контейнер стартовал, но сервис мёртвый.

Текущая глубина отката в инфраструктуре:

| Контейнер | HealthCmd | `Notify=healthy` | Откат |
| :--- | :--- | :--- | :--- |
| `04-memos` (obshaga) | есть | нет | при крахе на старте |
| `02-dashy`, `03-linkstack`, `01-nora` | нет | нет | при крахе на старте |

## Планировщик (наша настройка)

Базовый `podman-auto-update.timer` поставляется с Podman (`/usr/lib/systemd/user/`), по умолчанию выключен и имеет `OnCalendar=daily`, `Persistent=true` (догоняет пропущенный запуск после простоя ВМ).

Наш override — ежедневный старт в **случайный момент окна 03:00–04:00** (03:00 + случайная задержка до 1 часа):

```ini
# ~/.config/systemd/user/podman-auto-update.timer.d/override.conf
[Timer]
OnCalendar=
OnCalendar=*-*-* 03:00:00
RandomizedDelaySec=1h
```

> [!note] Нюанс override
> `OnCalendar` — списковая опция: сначала пустое присваивание (`OnCalendar=`) **сбрасывает** дефолтный `daily`, иначе сработают оба расписания.

Включение и проверка:

```bash
systemctl --user daemon-reload
systemctl --user enable --now podman-auto-update.timer
systemctl --user list-timers --no-pager   # NEXT внутри окна 03:00–04:00
```

Настройка входит в этап 2.4 гайда [[06_настройка_ВМ|«Настройка ВМ»]] и выполняется на каждой новой ВМ.

## Два триггера в нашей GitOps-схеме

1. **По пушу:** пуш в `homelab-deploy` → webhook → `sync-state.sh` → `podman auto-update` (образы, собранные вместе с конфигурацией).
2. **По таймеру:** ежедневно 03:00–04:00 → `podman-auto-update.service` → `podman auto-update` (образы, пересобранные в реестре без пуша — например, обновление базового образа в CI).

Триггеры суммируются и не конфликтуют: команда идемпотентна, повторный запуск без нового digest — no-op.

## Шпаргалка

```bash
# Проверить наличие обновлений, ничего не меняя
podman auto-update --dry-run

# Обновить всё, что pending, немедленно
podman auto-update

# Когда следующий автозапуск
systemctl --user list-timers --no-pager

# Логи последнего автообновления
journalctl --user -u podman-auto-update.service

# Раскрутить встроенные юниты таймера
systemctl --user cat podman-auto-update.timer
```

## Ограничения

- Обновляются только **мутабельные теги** (`:latest`). Digest-pinned образы не трогаются — осознанный tradeoff между воспроизводимостью и обновляемостью.
- Автообновление тянет **только образы**. Quadlet-файлы, env, конфиги — работа GitOps ([[03_gitops_агент]]): конфигурация → через git, образы → через реестр. Два независимых слоя.
- Сломанный образ из реестра, с которым справился health-aware rollback, будет рубить обновление до исправления в реестре — чинить источник.
- Пуш-модель не заметила бы сбой, если бы скрипт молча выходил — поэтому `sync-state.sh` при ошибке `git pull` падает с ненулевым кодом (webhook вернёт 500).
