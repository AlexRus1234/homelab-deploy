# SKLD00 — Сетевое хранилище (NAS)

> **Узел:** `SKLD00`
> **Роль:** Центральный Data-слой хоумлаба — файловое хранилище, базы данных, S3.
> **ОС:** Arch Linux
> **Сеть:** `172.20.50.0/16` (диапазон SKLD), 2.5 Gbps
> **Особенность:** К узлу подключена **ленточная библиотека** (LTO-4 / LTO-5) для резервного копирования в офлайн.

---

## 1. Аппаратная часть

| Компонент | Значение |
| :--- | :--- |
| **Корпус** | Jonsbo N4 (Mini-ITX, корзина горячей замены HDD, деревянная верхняя панель) |
| **CPU** | Intel Core i3 (Tiger Lake) — энергоэффективный |
| **RAM** | 24 ГБ (проверена Memtest; одна битая планка удалена) |
| **Системные SSD** | 2× NVMe SSD (гибридная разметка, см. ниже) |
| **HDD** | 6× HDD (основное хранилище, среди них WD Purple 4TB) |
| **Сеть** | 2.5 Gbps (упор скорости ~270 МБ/с) |
| **Лента** | LTO-4 / LTO-5 стример (оффлайн-бэкап) |

**Характеристики в простое:** абсолютно бесшувмен, низкое энергопотребление.

---

## 2. Сетевые адреса (macvlan)

SKLD00 — bare-metal узел, на котором поднят **слой баз данных и S3**. Каждый сервис БД имеет собственный виртуальный интерфейс (macvlan) в локальной сети — без NAT и проброса портов.

| Сервис | IP-адрес | Порт | Назначение |
| :--- | :--- | :--- | :--- |
| **Хост SKLD00 (Samba/SMB)** | `172.20.50.1` | 445 | Файловая шара `\\SKLD00\Share` |
| **PostgreSQL** | `172.20.50.10` | 5432 | Реляционная БД |
| **MongoDB** | `172.20.50.11` | 27017 | Документная БД (WiredTiger) |
| **Valkey (Redis)** | `172.20.50.12` | 6379 | Кэш в памяти |
| **MinIO (S3)** | `172.20.50.13` | 9000 / 9001 | Объектное хранилище / Web UI |

**Прямой линк (P2P, vmbr1) до YADR01:** сеть `172.21.6.0/24` (см. [Архитектура и сеть](../Инфраструктура/01_архитектура_и_сеть.md)); S3-endpoint RustFS — `172.21.6.249:9000`, PostgreSQL также слушает этот адрес.

> ⚠️ **Безопасность:** все БД слушают **только** свой macvlan-IP и адреса на P2P-линке (`172.21.6.x`). Слушать `0.0.0.0` или localhost запрещено.

## 3. Дисковая разметка (гибридная схема)

### NVMe (2 диска) — максимальная утилизация

| Раздел | ФС / Роль | Размер |
| :--- | :--- | :--- |
| **p1** | EFI Boot (FAT32) — на обоих дисках, загрузчик GRUB дублирован | ~512M |
| **p2** | Система (Root) — **Btrfs RAID1** (зеркало) | весь остаток корня |
| **p3** | Кэш загрузок — **Btrfs RAID0** (скорость), метаданные в RAID1 | 340 GiB |
| **p4** | ZFS Special — **ZFS Mirror** (ускорение метаданных массива) | 350 GiB |

### HDD (6 дисков) — основное хранилище

| Пул | Тип | Назначение |
| :--- | :--- | :--- |
| **tank** | **RAIDZ2** (аналог RAID6, переживает смерть 2 любых HDD) | Основное хранилище |
| **tank (special)** | ZFS Mirror из 2 разделов NVMe (p4) | Метаданные и мелкие файлы → мгновенный листинг |

### Тюнинг ZFS (`tank/data`)
- `sync=disabled` — отключение синхронной записи (убирает нагрузку на ZIL, ускоряет SMB в разы)
- `special_small_blocks=0` — мелкие блоки не пишутся на потребительские SSD (спасает их от износа)
- `compression=zstd` — сжатие «на лету» (экономит место)
- `recordsize`: PostgreSQL `16k`, MongoDB `64k` (под движок WiredTiger)

**Обслуживание ZFS:**
- `sudo zpool scrub tank` — ручная проверка целостности
- Автоматический Scrub — 1-го числа каждого месяца (таймер)

| Путь | Что хранится |
| :--- | :--- |
| `/tank/data` | Основной датасет ZFS (шара SMB `Share`) |

| `/var/lib/mongodb` | Данные MongoDB |
| `/var/lib/valkey` | Данные Valkey/Redis |
| `/srv/minio/data` | Данные MinIO (стандарт Arch Wiki) |
| `/etc/minio/minio.conf` | Конфиг MinIO (`chmod 600`, содержит ключи) |

## 5. Сервисы на SKLD00

### А. Файловый сервер (Samba)
- **Шара:** `\\SKLD00\Share` → путь `/tank/data`
- **Обнаружение:** `wsdd` (Windows), `avahi` (Linux/macOS, иконка RackMac)
- **Пользователь:** `<user>` (пароль задан через `smbpasswd`)
- **Костыль `nas-kickstart`:** systemd-служба ждёт 20 сек после загрузки и принудительно поднимает `smb nmb wsdd avahi-daemon` (решает проблему падения Samba при медленном старте сети)
- **VFS:** `catia fruit streams_xattr` — оптимизации под Apple/ZFS/Windows

### Б. Базы данных (bare-metal, не в Docker)
> **Архитектурное решение:** БД вынесены из контейнеров на Proxmox на «голое железо» NAS — устранение оверхеда виртуализации, прямой доступ к ZFS, централизованный Data-слой.

| БД | Особенности конфигурации |
| :--- | :--- |
| **PostgreSQL** | `listen_addresses` — macvlan-IP `172.20.50.10` + адреса P2P-линка (`172.21.6.249` и др.); `pg_hba.conf`: `scram-sha-256` для `172.20.0.0/16` и `172.21.6.0/24`. БД: `forgejo`, `synapse`, `authentik`, `khrazhevnik`. |
| **MongoDB** | `bindIp: 172.20.50.11,172.21.6.255`. Пользователи привязаны к БД (`authSource`) — при подключении извне обязательно `?authSource=имя_бд`. |
| **Valkey** | Свободный форк Redis (Arch Linux). Глобальный пароль `requirepass`, без классических логинов. |
| **MinIO** | S3-хранилище по HTTP API. UI: `http://172.20.50.13:9001`. Бакеты: `matrix-media`, `forgejo-data`, `khrazhevnik` и др. |

### В. Мониторинг и утилиты
| Сервис | Порт / Команда |
| :--- | :--- |
| **Netdata** | Web UI: `:19999` |
| **Smartd** | Следит за здоровьем дисков |
| **Reflector** | Авто-выбор быстрых зеркал pacman (ежедневно) |
| `ncdu` / `htop` / `btop` | Анализ места и нагрузки |

---

## 6. Системные службы systemd (пользовательские)

| Служба | Назначение |
| :--- | :--- |
| `nas-kickstart.service` | Принудительный старт Samba/WSDD/Avahi через 20с после загрузки |
| `zfs-force-import.service` | «Упорный» импорт пула `tank` (retry-loop, ждёт 5с между попытками) |
| `smartd` / `reflector.timer` | Мониторинг дисков / обновление зеркал |

---

## 7. Бэкапы
- **Сама система (Root):** Btrfs RAID1 + **Snapper** (автоснимки перед `pacman`, пункт в GRUB для отката)
- **Данные ZFS:** автоматический Scrub + ленточная библиотека LTO
- **БД Proxmox-контейнеров:** бэкапятся на PBS, а тяжёлые данные (медиа) лежат на SKLD00 (см. [08 — Proxmox: бекап PBS](../Настройка/08_Proxmox_бекап_PBS.md))
