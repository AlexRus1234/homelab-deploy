# SHLZ00 — Роутер (Sovereign Edge Gateway)

> **Узел:** `SHLZ00`
> **Роль:** Центральный маршрутизатор, шлюз в интернет, DNS-сервер, CA (центр сертификации), SOCKS5-прокси, IPS/IDS, QoS-шейпер.
> **ОС:** Arch Linux
> **Сеть:** LAN `172.20.0.1/16`, IoT `172.22.0.1/16`, Rescue `192.168.99.1/24`
> **WAN:** DHCP от провайдера (MAC клонирован со старого роутера)

---

## 1. Аппаратная часть

| Компонент | Значение |
| :--- | :--- |
| **Платформа** | GenMachine (серебристо-белый кубический мини-ПК) |
| **CPU** | AMD Ryzen 3 5425U (сверхпроизводительное решение для роутера) |
| **RAM** | 8 ГБ (распаяна на плате, нерасширяемо — с запасом для роутера) |
| **Сеть** | **4× порта 2.5 Gbps** RJ-45 + 2× USB-C, 2× USB-A, HDMI |
| **Накопитель** | M.2 SSD (легкий доступ) |
| **Охлаждение** | Активное (вентилятор); термопаста заменена с китайской «пластилиновой» на нормальную |
| **Потребление** | 6–7 Вт в простое |

**Температурный режим:** ~40–42°C в простое, до 84°C под 15-минутной нагрузкой (стабильно).

> ⚠️ **Нюанс железа:** мини-ПК нагревается сильнее в **выключенном** состоянии, чем во включенном (вероятно греется SSD). Не оставлять выключенным в розетке надолго.

## 2. Топология интерфейсов

| Порт | Интерфейс | Роль | IP / Подсеть |
| :--- | :--- | :--- | :--- |
| **1 (Левый)** | `enp6s0` | **WAN** (Интернет) | DHCP от провайдера, MAC `AA:BB:CC:DD:EE:FF` (клон старого роутера) |
| **2** | `enp5s0` | **LAN** (Основная сеть) | `172.20.0.1/16` |
| **3** | `enp3s0` | **IoT** (Сеть вещей) | `172.22.0.1/16` |
| **4 (Правый)** | `enp1s0` | **RESCUE** (Аварийный) | `192.168.99.1/24` |

**DHCP:** LAN `172.20.255.10–250/16` (12ч), IoT `172.22.0.10–250/16` (12ч), Rescue `192.168.99.10–20/24` (1ч).

> Все IP поднимаются через `ConfigureWithoutCarrier=yes` — адреса висят на интерфейсах даже без подключённого кабеля.

## 4. Сетевые службы

### А. Firewall + NAT (nftables)
- `flush ruleset` → таблица `nat` (masquerade только на `enp6s0`) + таблица `filter` (input: drop, established/lo/icmp разрешены; доступ к роутеру только из LAN/IoT/Rescue, **не из WAN**)

### Б. DNS «Сэндвич» (гибридный резолвер)
Цепочка: **Клиент → AdGuard (53) → dnsmasq (5353) → Unbound (5335) → Интернет**

| Сервис | Роль | Порт | Веб-интерфейс |
| :--- | :--- | :--- | :--- |
| **AdGuard Home** | Блокировка рекламы, UI, frontend | 53 | `http://172.20.0.1:3000` |
| **dnsmasq** | DHCP-сервер, локальные домены `.lan` | 5353 | — |
| **Unbound** | Рекурсивный резолвер (вместо 8.8.8.8) | 5335 | — |

### В. QoS — умный шейпинг (борьба с Bufferbloat)
- **Метод:** `tc-cake` + Python-скрипт Autorate (`/opt/smart-shaper.py`)
- **Логика:** пингует шлюз провайдера. При пинге > 50 мс снижает скорость на 10%, при норме повышает на 2% (раз в 10с). Лимиты: `MAX_SPEED=900 Мбит`, `MIN_SPEED=50 Мбит`
- **Служба:** `smart-shaper.service` → `journalctl -u smart-shaper -f`
- **irqbalance** — распределение прерываний по ядрам CPU

### Г. SOCKS5-прокси (sing-box)
- **Порт:** `1080` (слушает `0.0.0.0`)
- **Назначение:** обход блокировок для внутренних сервисов домашней сети
- **Outbound:** VLESS+Reality через внешний сервер
- **Конфиг:** `/etc/sing-box/config.json`

### Д. Центр сертификации (Step-CA) — PKI
- **ПО:** `step-ca` + `step-cli`, работает от системного пользователя `step`
- **Адрес CA:** `https://172.20.0.1:9000`
- **ACME-эндпоинт:** `https://172.20.0.1:9000/acme/acme/directory` (используется Caddy для авто-выпуска сертификатов зоны `.internal`)
- **Провижинер ACME:** `acme` (добавлен отдельно)
- **Корневой сертификат:** раздаётся по сети `https://172.20.0.1:9000/roots.pem` и устанавливается на все устройства (Windows/Android/Linux) для «зелёного замочка»
- **Проверка здоровья:** `curl -k https://172.20.0.1:9000/health` → `{"status":"ok"}`

## 5. Безопасность (IDS/IPS)

| Компонент | Роль |
| :--- | :--- |
| **RAM-диск для логов** | `tmpfs /var/log/ids-ram tmpfs defaults,size=512M` — SSD не изнашивается |
| **Zeek (Docker)** | Сетевая телеметрия, путь `~/uCPE/zeek/` |
| **Suricata (Docker)** | Обнаружение вторжений (IDS), путь `~/uCPE/suricata/` |
| **CrowdSec (native)** | Активный бан (IPS): читает логи Suricata → банит в nftables. Баунсер `crowdsec-firewall-bouncer` (nftables mode). Конфиг: `/etc/crowdsec/` |

## 6. Внутренний контроль (Ops)

| Сервис | Назначение / Команда |
| :--- | :--- |
| **arpwatch** | Слежка за сменой MAC (защита от спуфинга, только управляемый свитч). `journalctl -u arpwatch@enp5s0` |
| **lldpd** | Топология сети (какой порт свитча). `lldpcli show neighbors` |
| **Node Exporter** | Метрики для Prometheus, порт `9100` |
| **iperf3** | Сервер замера скорости, порт `5201` |
| **Vector** | Забирает логи из RAM-диска. Конфиг `/etc/vector/vector.toml`. `journalctl -u vector -f` |
| **Etckeeper** | Все конфиги `/etc` под Git — откат `sudo etckeeper vcs checkout /etc/filename`, история `sudo etckeeper vcs log` |
| **Chrony** | Синхронизация времени |

## 7. Быстрые команды диагностики

| Задача | Команда |
| :--- | :--- |
